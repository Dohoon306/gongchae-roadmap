# 한국 채용 공고 데이터 소스 조사

- 조사일: 2026-11-24
- 목적: 전공/이력서 기반 공고 추천 + 회사별 준비 로드맵 웹사이트(Spring Boot, 개인 1명, 비상업 연습 프로젝트)
- 확정 요구: **추천에 마감된 과거 공고를 반드시 사용한다.** 그래서 "과거 공고를 조회할 수 있는가"를 결론의 핵심 기준으로 삼았다.
- 조사 방법: 각 서비스의 공식 페이지(공공데이터포털 상세 페이지, 공식 API 가이드, 이용약관, robots.txt)를 직접 읽었다. 회원가입, 키 신청, 실제 API 호출은 하지 않았다.
- 표기
  - **[확인]** 공식 페이지에서 직접 읽은 사실
  - **[추정]** 공식 페이지의 문구나 파라미터를 보고 추론한 내용
  - **[미확인]** 읽은 페이지에 정보가 없거나 페이지를 읽지 못한 경우
  - **[비공식]** 제3자 자료(GitHub 등)

## 1. 추천 결론

### 1순위: 공공데이터포털 「재정경제부_공공기관 채용정보 조회서비스」(잡알리오 API, data.go.kr 15125273)

선정 이유(과거 공고 기준을 가장 무겁게 봤다):

1. **과거 공고를 조회할 수단이 요청 파라미터에 있는 유일한 무료 공식 API다.** [확인] 진행여부 `ongoingYn`(Y/N)과 공시 시작일 범위 `pbancBgngYmd`/`pbancEndYmd`가 있다. 공식 예시도 과거 기간(2023-07-01~2023-12-10)을 조회한다. [추정] `ongoingYn=N`이 마감 공고를 뜻할 것으로 보이며, 실제로 반환되는지와 몇 년 전까지 조회되는지는 키를 받아 호출해 봐야 안다.
2. **이용 조건이 가장 자유롭다.** [확인] 무료이고 이용허락범위가 "제한 없음"이다. 개인 비상업 프로젝트에서 받은 데이터를 저장하고 AI로 분석·재가공해도 약관과 충돌하지 않는다. 고용24는 "변경금지"(공공누리 4유형)이고, 원티드와 잡코리아는 개인에게 API를 주지 않는다.
3. **추천과 로드맵에 필요한 필드에 가장 가깝다.** [확인] NCS 직무코드, 학력조건, 고용유형, 근무지역으로 필터할 수 있고, 상세조회가 "채용전형단계"와 "채용첨부파일 메타정보"를 준다. 전형 단계는 로드맵을 그리는 데 바로 쓰인다.
4. **공고 PDF를 직접 가져올 가능성이 있는 유일한 후보다.** [확인] 상세조회가 첨부파일 메타정보를 준다. [미확인] 다운로드 URL이 들어 있는지는 확인하지 못했다.

한계:
- **공공기관(공운법상 약 370개 기관)만 다룬다.** 민간 기업 공고는 없다. [추정]
- [미확인] 응답 필드의 영문 이름(자격요건 본문, 전공, 마감일 필드 등), 승인 방식(자동승인/심의승인), 개발계정 일일 트래픽은 공식 페이지에 나오지 않았다. 로그인 후 활용신청 화면이나 첨부된 명세서에서 확인해야 한다.
- 과거 공고 보강용으로 같은 기관의 파일데이터(15050508, 최근 한 달치 CSV)와 인사혁신처 공공채용정보(15151560, 2025년 1년치 CSV)를 함께 쓸 수 있다. 다만 두 파일 모두 자격요건 본문은 없다.

민간 기업까지 넓히려면 **2순위는 사람인 API**다.
- [확인] 등록일 범위(`published_min`/`published_max`)와 마감일(`deadline`)로 검색할 수 있고, 응답의 `active`(1 진행중, 0 마감)로 마감 여부를 구분한다. 일일 호출은 최대 500회다.
- 단점: [확인] 이용신청 후 승인을 받아야 한다. [미확인] 개인도 승인을 받을 수 있는지, 마감 공고가 실제로 검색되는지는 확인하지 못했다. [확인] 응답에 자격요건, 전공, 전형 본문이 없고 제목, 키워드, 코드값, URL만 있다.

### 키 발급 전 대안: 직접 만든 샘플 데이터와 비교

| 기준 | 잡알리오 API (1순위) | 직접 만든 샘플 데이터 |
|---|---|---|
| 시작 시점 | 활용신청 승인 후 (승인 소요 시간 미확인) | 즉시 |

권장 진행 순서:
1. 지금 잡알리오 API 활용신청을 넣는다. 사람인도 필요하면 함께 신청한다.
2. 승인을 기다리는 동안 잡알리오의 요청 파라미터 구조(NCS코드, 학력조건, 고용유형, 근무지역, 진행여부, 공시기간, 전형단계, 첨부파일)를 본뜬 샘플 JSON 20~50건(마감 공고 포함)과, 실제 공개 CSV(15151560, 15050508)를 섞어 개발을 시작한다.
3. 데이터 소스는 인터페이스 하나로 감싼다(예: 공고 조회 포트). 키가 나오면 구현체만 API용으로 바꾼다.

### 첨부파일(공고 PDF) 전략, 후보별 요약 (요구 7)

- **PDF 직접 가져오기 가능성 있음:** 잡알리오 API. 상세조회가 첨부파일 메타정보를 준다 [확인]. 실제 다운로드 URL이 들어 있는지는 [미확인]이므로 키 발급 후 첫 호출에서 확인한다.
- **원문 페이지 링크만 줌 → 사용자가 직접 PDF를 받아 올리는 방식:** 사람인(`url`), 고용24/워크넷(채용정보URL), 잡코리아(상세요강 URL).
- **링크도 불확실:** 원티드(문서 미확인, 개인은 이용 불가), 공개 파일데이터(대부분 URL 컬럼 없음).

## 3. 후보별 상세

### 3.1 잡알리오 API: 재정경제부_공공기관 채용정보 조회서비스

- 출처: https://www.data.go.kr/data/15125273/openapi.do
- [확인] 제공기관은 재정경제부 경영관리과다. 무료이고, 오픈API(REST, JSON+XML, `resultType` 기본값 json), 실시간 갱신이다. 등록 2023-12-01, 수정 2026-07-01.
- [확인] 호출 주소는 `https://apis.data.go.kr/1051000/recruitment`이고, 공공데이터포털에서 받은 `serviceKey`가 필요하다.
- [확인] 오퍼레이션 2개
  - 채용공시 목록조회: `pageNo`, `numOfRows`, `ncsCdLst`(NCS코드목록), `acbgCondLst`(학력조건), `hireTypeLst`(고용유형), `instClsf`(기관분류), `instType`(기관유형), `recrutSe`(채용구분), `replmprYn`(대체인력여부), `workRgnLst`(근무지역), `recrutPbancTtl`(공시제목), `pblntInstCd`(기관코드), `ongoingYn`(진행여부 Y/N), `pbancBgngYmd`/`pbancEndYmd`(공시 시작일 기준 조회기간)
  - 채용공시 상세조회: 필수 `sn`(채용공시 일련번호). "채용전형단계, 채용첨부파일 메타정보"를 준다.
- [확인] 설명문에 공고 제목, 접수기간, 채용직무 및 인원, 채용 전형 단계, 접수방법, 첨부파일 메타정보가 나온다. 하지만 페이지의 출력 표에는 `result`, `resultCode`, `resultMsg`, `totalCount`만 있다. 상세 필드명은 "코드정의서 첨부파일 참조"로 되어 있다.
- [확인] 이용허락범위: "제한 없음". 포털 이용약관 제14조 ⑤에 따라 제공기관 시스템에 지장을 주는 이용은 제한될 수 있다(https://www.data.go.kr/ugs/selectPortalPolicyView.do).
- [미확인] 승인 방식(자동/심의), 승인 소요 시간, 개발계정 트래픽. 상세 페이지에도 이용가이드에도 없었다.
- [비공식] 제3자 MCP 서버 코드(https://github.com/iapke486-arch/job-mcp-server)는 `/list` 경로를 호출하고 응답 필드 `instNm`(기관명), `recrutPbancTtl`(공고제목)을 쓴다. 첨부파일 필드명은 이 코드에서도 확인되지 않았다.
- 대상: [확인] 공공기관이 수시공시하는 채용공시. 같은 기관 파일데이터의 설명은 "공공기관의 운영에 관한 법률에 따라 지정된 370개 공공기관"이다.
