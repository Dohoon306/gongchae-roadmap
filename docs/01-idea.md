# 01. 아이디어

상태: 확정 (2026-11-24). 2026-11-26에 범위를 바꿨다(공고 선택, 통합 로드맵, 인프라, 배포). 경위는 `docs/02-design-decisions.md`.

## 한 줄 설명

공공기관 취준생이 자신에게 맞는 채용 공고를 찾고, 지원할 기관별 준비 계획을 세울 수 있게 돕는 웹사이트.

## 사용자 흐름

1. **가입·로그인**: 아이디와 비밀번호로 가입한다. (2차)
2. **입력**: 전공 분야 카테고리를 고르거나, 이력서·자기소개서를 올린다.
3. **분석**: AI가 내용을 읽고 전공, 기술, 경험, 관심 직무를 뽑는다.
4. **추천**: 맞는 채용 공고를 여러 개, 이유와 함께 추천한다. 지금 열려 있는 공고뿐 아니라 마감된 과거 공고도 보여준다.
5. **선택**: 사용자가 지원하려는 공고들을 고른다. 화면에서는 기관별로 묶어 보여준다. (2026-11-26 변경: 기관 → 공고. `docs/02-design-decisions.md` Q2)
6. **로드맵**: 고른 공고들을 하나의 통합 로드맵으로 만든다. 단계마다 어느 공고에 해당하는지 표시하고, 공고들의 일정을 함께 보고 준비 일정을 조정한다. 달력이나 간트 차트로도 보여준다. (시각화는 2차. 2026-11-26 변경: 공고별 로드맵 → 통합 로드맵, 일정 조정을 1차로. `docs/02-design-decisions.md` Q8)

## 결정

| 항목 | 결정 |
|---|---|
| 대상 | 공공기관 공고만 다룬다 |
| 공고 데이터 출처 | 공공데이터포털 잡알리오 API(공공기관 채용정보 조회서비스). 키 발급 전까지는 같은 구조의 샘플 데이터로 개발하고, 공고를 가져오는 부분은 교체할 수 있게 만든다. 근거: `docs/research/job-data-sources.md` |
| 열려 있지 않은 공고 | 마감된 과거 공고를 보여준다 |
| 전공 카테고리 | 잡알리오가 쓰는 NCS 직무 분류를 그대로 쓴다 |
| 이력서 입력 | PDF 업로드, 텍스트 붙여넣기 |
| 이력서 원본 | 분석 결과만 저장하고 원본 파일은 분석 후 삭제한다 |
| 로드맵 형태 | 고른 공고들을 담은 통합 로드맵 하나(준비 단계와 할 일 목록, 일정 조정 포함) + 달력·간트 차트 시각화. 세부는 `docs/02-design-decisions.md` Q8~Q11 |
| 로그인 | 아이디·비밀번호로 가입하고 로그인한다 |
| 공고 원문 | 가능하면 실제 공고 PDF를 직접 가져온다. 안 되면 채용 사이트 링크를 주고 사용자가 PDF를 직접 받아 올린다 |
| 백엔드 | Spring Boot |
| DB | 실행은 MySQL(Docker Compose), 테스트는 메모리 H2 |
| 프론트엔드 | React (Vite, TypeScript) |
| 저장소 구조 | 한 저장소에 `backend/`와 `frontend/` |
| AI 연동 | OpenAI API로 시작한다. AI 호출 부분은 교체할 수 있게 만든다 |
| 실행 환경 | 1차에는 배포하지 않고 내 컴퓨터에서 실행한다. 2차에 AWS EC2에 배포한다 |
| 인프라 | 포트폴리오용으로 넣는다. 1차: Docker Compose(프론트엔드, 백엔드, MySQL 컨테이너 셋)와 내 컴퓨터의 Jenkins(빌드·테스트). 2차: Jenkins로 AWS EC2 자동 배포. 세부는 `docs/02-design-decisions.md` Q24~Q26 |

## 개발 단계

| 단계 | 범위 |
|---|---|
| 1차 기능 | 입력(직무 분류, 이력서) → AI 분석 → 공고 추천 → 공고 선택 → 통합 로드맵(준비 단계와 할 일, 일정 조정). 로그인 없이 한 번의 흐름만 동작한다 |
| 1차 인프라 | 기능이 모두 끝난 뒤에 한다. 전체 실행용 Docker Compose(컨테이너 셋), 내 컴퓨터의 Jenkins(빌드·테스트). 배포는 하지 않는다 |
| 2차 | 가입·로그인, 달력·간트 차트, 공고 PDF 가져오기와 직접 올리기, Jenkins로 AWS EC2 자동 배포(가입·로그인이 끝난 뒤) |
