# 03. 1차 화면 디자인

1차 화면 세 개(입력, 추천, 로드맵)의 구성, 공통 요소, 상태별 모습을 적는다. 구현 세션은 이 문서와 이슈(#1, #5~#15)만 보고 화면을 만든다. 용어는 `GLOSSARY.md`를 따른다.

2026-11-27에 정했다. 사용자가 고른 것은 세 가지다.

- 시안은 Figma로 만든다.
- 분위기는 차분하고 믿음직하게: 흰 바탕, 남색 강조색 하나, 넉넉한 여백, 그림자 없이 테두리로 나눈 카드.
- 로드맵 화면은 준비 단계 카드 안에 "공고별 기한"과 "할 일"을 함께 둔다(맨 위에 공고 × 전형 종류 표를 두는 안은 고르지 않았다).

1차 범위 밖은 그리지 않았다: 로그인, 달력·간트 차트, 지원자 프로필 수정, 공고 PDF.

## 공통 요소

#5가 만드는 것은 버튼, 진행 중 표시, 실패 안내와 다시 시도 버튼, 화면 틀(머리글), 색과 글꼴 값이다. 나머지는 처음 쓰는 티켓에서 만든다. Figma의 `0 공통 요소` 쪽에 같은 이름의 컴포넌트가 있다.

CSS는 일반 CSS 파일과 CSS 변수로 충분하다. UI 라이브러리를 쓰지 않아도 만들 수 있게 그렸다.

### 색

색의 뜻은 고정이다. 남색은 강조와 조작, 청록은 사용자가 입력한 날짜, 노랑은 겹침, 빨강은 실패·오류·기한 지남, 회색은 날짜 미정과 마감 공고다. 색만으로 뜻을 전하지 않고 글이나 아이콘을 항상 함께 둔다.

### 글꼴

Noto Sans KR. 굵기는 400, 500, 700만 쓴다. 대체 글꼴은 `system-ui, sans-serif`다. 글꼴을 넣는 방법(패키지나 링크)은 #5에서 고른다.

| 이름 | 크기 / 줄 높이 | 굵기 | 쓰는 곳 |
|---|---|---|---|
| title | 28 / 38 | 700 | 화면 제목 |
| h2 | 20 / 30 | 700 | 구역 제목, 준비 단계 이름 |
| h3 | 17 / 26 | 700 | 카드 제목, 공고 제목 |
| body | 15 / 24 | 400 | 본문, 할 일 내용 |
| body-strong | 15 / 24 | 500 | 버튼, 기관 이름, 날짜 |
| small | 13 / 20 | 400 | 보조 설명, 안내 |
| small-strong | 13 / 20 | 500 | 라벨, 표시 |

### 간격, 모서리, 테두리

- 간격은 4의 배수다: 4, 8, 12, 16, 20, 24, 28, 32, 40.
- 모서리: 표시 4, 입력 칸과 버튼 8, 안내 상자 10, 카드 12, 칩은 완전히 둥글게.
- 그림자는 쓰지 않는다. 카드는 흰 바탕에 `--border-default` 1px 테두리다.

### 화면 틀

- 머리글: 높이 64, 흰 바탕, 아래 선 1px. 왼쪽에 서비스 이름 "공채 로드맵"(h3, 남색, 누르면 입력 화면), 오른쪽에 단계 표시 "1 입력 — 2 추천 — 3 로드맵".
  - 지금 단계: 남색 동그라미에 흰 숫자, 글은 body-strong.
  - 지나온 단계: 옅은 남색 동그라미에 체크, 글은 남색 밑줄. 누르면 그 화면으로 간다(추천 화면에서 "입력", 로드맵 화면에서 "입력"과 "추천").
  - 아직 가지 않은 단계: 테두리만 있는 동그라미, 글은 `--text-muted`. 누를 수 없다.
- 본문: 너비 880, 가운데 정렬, 위아래 여백 40, 요소 사이 24. 화면 바탕은 `--bg-page`.
- 좁은 화면(920px보다 좁을 때): 본문을 화면 너비에 맞추고 좌우 여백 16, 카드 안 여백 20. 가로로 놓인 줄(공고별 기한, 할 일, 아래 고정 줄)은 오른쪽 부분이 아래로 내려가 세로로 쌓인다. 좁은 화면 시안은 따로 그리지 않았다.

### 버튼

| 종류 | 모습 | 쓰는 곳 |
|---|---|---|
| 강조 | 높이 44, 좌우 여백 20, 남색 바탕, 흰 글(body-strong) | 화면마다 하나: "추천 받기", "로드맵 만들기" |
| 강조, 진행 중 | 강조 버튼 글 앞에 도는 동그라미. 누를 수 없다 | AI를 부르지 않는 짧은 기다림 |
| 강조, 비활성 | `--neutral-subtle` 바탕, `--text-muted` 글 | 누를 수 없을 때 |
| 보조 | 흰 바탕, `--border-strong` 테두리, 본문색 글 | "입력부터 다시 하기"(빈 화면), "취소" |
| 작게 | 높이 36, 좌우 여백 14, 글은 small-strong. 강조와 보조 두 가지 | 날짜 "저장"·"취소", "다시 시도", "파일 고르기" |
| 글 | 바탕 없이 남색 밑줄 글 | "입력부터 다시 하기", "로드맵 보기", "빼기", "넣은 날짜 지우기" |

초점은 모든 조작 요소에 남색 2px 테두리(outline)로 보인다.

### 직무 분류 칩

높이 40, 좌우 여백 14, 완전히 둥근 모서리. `<button aria-pressed>`로 만든다.

- 기본: 흰 바탕, `--border-strong` 테두리.
- 고름: 남색 바탕, 흰 글(body-strong), 글 앞에 체크.
- 흐림: 3개를 고른 뒤 나머지 21개. `--bg-subtle` 바탕, `--text-muted` 글. 누를 수는 있다(아래 "입력" 참고).

### 표시

높이 24, 좌우 여백 8, 모서리 4, 글은 small-strong.

| 표시 | 색 | 아이콘 | 쓰는 곳 |
|---|---|---|---|
| 회색 | `--neutral-subtle` 바탕 | 없음 | "마감 공고", "접수 마감됨", "기한 날짜 미정", "선택", 추천 카드의 직무 분류, 지원자 프로필의 기술 |
| 남색 | 옅은 남색 바탕과 테두리 | 없음 | "가장 이른 기한 12.04 (금)", 지원자 프로필의 관심 직무 분류 |
| 겹침 | 노랑 | 세모 느낌표 | "겹침" |
| 기한 지남 | 빨강 | 동그라미 느낌표 | "기한 지남" |
| 직접 입력 | 청록 | 연필 | "직접 입력" |

### 체크 칸, 입력 칸, 카드

- 체크 칸: 22×22, 모서리 5. 끔은 흰 바탕에 테두리, 켬은 남색 바탕에 흰 체크. 실제 `<input type="checkbox">`를 쓰고, 추천 카드 전체를 눌러도 켜지고 꺼진다.
- 입력 칸: 라벨(small-strong, `--text-secondary`)이 위, 칸은 높이 44, 모서리 8, `--border-strong` 테두리. 초점은 남색 2px, 오류는 빨간 테두리와 칸 아래 빨간 글(small).
- 카드: 흰 바탕, 테두리 1px, 모서리 12, 안 여백 28, 안의 요소 사이 20.

### 날짜 버튼

로드맵의 공고별 기한에 쓴다. 높이 36, 좌우 여백 12, 모서리 8. 셋 다 누르면 그 자리가 날짜를 넣는 칸으로 바뀐다.

| 종류 | 모습 |
|---|---|
| 공고의 날짜 | 흰 바탕, `--border-default` 테두리, 날짜(body-strong), 회색 연필 |
| 사용자가 입력한 날짜 | 청록 바탕과 테두리, 청록 날짜, 청록 연필. 버튼 왼쪽에 "직접 입력" 표시가 붙는다 |
| 날짜 미정 | 흰 바탕, 점선 테두리, 달력 아이콘, "날짜 미정"(`--text-secondary`), "날짜 넣기"(남색 small-strong) |

### 진행 중 표시

AI를 기다리는 동안 보여 준다. 옅은 남색 상자(모서리 10, 안 여백 20)에 도는 동그라미(24), 제목(body-strong), 설명(small, `--text-secondary`).

- 설명에는 항상 "최대 1분쯤 걸릴 수 있습니다. 이 화면을 닫지 말고 기다려 주세요."가 들어간다(제한 시간이 60초다).
- `role="status"`로 만든다. 동그라미는 1초에 한 바퀴 돌고, 움직임 줄이기 설정(`prefers-reduced-motion`)이면 돌지 않는다.
- 진행 중 표시가 떠 있는 동안 그 화면의 입력과 버튼은 누를 수 없고 흐리게(불투명도 0.55) 보인다.
- 취소 버튼은 없다.

### 실패 안내와 다시 시도 버튼

AI 실패 오류를 받으면 진행 중 표시가 있던 자리에 보여 준다. 옅은 빨강 상자에 동그라미 느낌표(24), 제목(body-strong), 설명(small), 오른쪽에 "다시 시도" 버튼(작게, 보조). `role="alert"`로 만든다.

- "다시 시도"는 같은 요청을 다시 보낸다. 누르면 실패 안내가 진행 중 표시로 바뀐다.
- 설명에는 무엇이 남아 있는지를 적는다(입력한 내용, 지원자 프로필, 고른 공고, 이전 로드맵).
- AI 실패가 아닌 오류(입력 거절)는 실패 안내가 아니라 해당 칸 아래의 빨간 글로 보여 준다. 서버가 준 한국어 메시지를 그대로 쓴다.

### 안내 상자

한 줄짜리 알림이다. 아이콘(16)과 글(small), 모서리 8, 안 여백 위아래 10·좌우 12.

- 정보: `--bg-subtle` 바탕, 동그라미 i. 예: "날짜 미정 5곳…".
- 주의: 노랑 바탕과 테두리, 세모 느낌표. 예: 직무 분류 4개째 선택 막힘.
- 오류: 빨강 바탕과 테두리, 동그라미 느낌표. 예: 빈 제출.

### 날짜 표기

- 형식은 `MM.DD (요일)`이다. 예: `12.19 (토)`.
- 로드맵 화면에서는 로드맵을 만든 날과 해가 다르면 `YYYY.MM.DD (요일)`로 쓴다. 예: `2027.01.13 (수)`.
- 추천 화면의 접수 기간은 항상 연도를 붙인다: `2026.11.16 (월) ~ 2026.12.11 (금)`. 전형 단계의 날짜는 접수 마감일과 해가 다를 때만 연도를 붙인다.
- 할 일의 기간은 `11.27 (금) ~ 11.28 (토)` 뒤에 날 수 `2일`을 회색으로 붙인다. 하루면 `12.03 (목)`과 `1일`이다. 날 수는 화면이 계산한다.
- 날짜를 넣는 칸은 `<input type="date">`를 쓴다.

## 화면 1: 입력

주소는 `/`다. 머리글의 단계는 1이다. 시안: 입력 / 01~06.

### 구성 (위에서 아래로)

1. **제목**: "맞는 공고 찾기"(title). 아래에 "관심 직무 분류를 고르거나 이력서·자기소개서를 넣으면, 맞는 공고를 순위와 이유와 함께 추천합니다. 가입 없이 바로 시작합니다."(body, `--text-secondary`).
2. **관심 직무 분류 카드**
   - 제목 줄: 왼쪽에 "관심 직무 분류"(h3)와 "1개에서 3개까지 고를 수 있습니다. 이력서·자기소개서를 넣으면 고르지 않아도 됩니다."(small). 오른쪽에 고른 개수 "2 / 3 고름"(둥근 알약 모양, 0개면 회색, 1개부터 옅은 남색).
   - 직무 분류 칩 24개. 목록 조회가 준 순서대로 놓고, 줄이 차면 다음 줄로 넘긴다(칩 사이 8).
3. **이력서·자기소개서 카드**
   - 제목 "이력서·자기소개서"(h3) 옆에 회색 표시 "선택". 아래에 "넣으면 AI가 전공, 기술, 경험을 읽고 공고마다 추천 이유를 씁니다. PDF와 글 중 하나만 넣을 수 있습니다."(small).
   - 탭 두 개: "PDF 올리기"(처음에 열려 있음), "글 붙여넣기". `--bg-subtle` 바탕의 둥근 띠 안에 놓고, 열린 탭만 흰 바탕이다.
   - PDF 올리기 탭: 점선 테두리 상자 가운데에 파일 아이콘, "PDF 파일을 골라 주세요"(body-strong), "PDF만 올릴 수 있습니다. 5MB까지."(small), "파일 고르기" 버튼(작게, 보조). 끌어다 놓기는 만들지 않는다. 파일을 고르면 상자가 한 줄로 바뀐다: 파일 아이콘, 파일 이름(body-strong)과 "PDF · 1.2MB"(small), 오른쪽에 "빼기"(글 버튼).
   - 글 붙여넣기 탭: 높이 220의 여러 줄 입력 칸. 자리 표시 글은 "이력서·자기소개서 글을 여기에 붙여넣어 주세요." 칸 아래 오른쪽에 글자 수 "284 / 20,000자"(small-strong, `--text-muted`).
   - "가릴 이름 (선택)" 입력 칸(너비 440). 자리 표시 글 "예: 홍길동". 아래에 "이력서에 적힌 이름을 넣으면 AI에 보내기 전에 [이름]으로 가립니다. 이 이름은 저장하지 않습니다."(small). 두 탭 모두에서 보인다.
   - 개인정보 안내 상자(`--bg-subtle`, 모서리 10, 안 여백 16): 제목 "입력한 내용을 이렇게 다룹니다"(small-strong)와 세 줄(small).
     - "전화번호, 이메일, 주민등록번호와 이름은 AI에 보내기 전에 가립니다. 주소는 가리지 않으니 필요하면 지우고 넣어 주세요."
     - "올린 파일과 붙여넣은 글은 저장하지 않습니다."
     - "실제 AI 분석을 켜면 입력한 내용이 OpenAI로 전송됩니다."
4. **작업 영역**: "추천 받기" 강조 버튼(본문 너비 가득). 제출 뒤에는 이 자리가 진행 중 표시나 실패 안내로 바뀐다.

### 동작

- 직무 분류 칩을 누르면 고름과 기본이 바뀐다. 3개를 고르면 나머지 칩이 흐림이 된다. 흐린 칩을 누르면 고르지 않고, 칩 목록 아래에 주의 안내 상자가 나온다: "직무 분류는 3개까지 고를 수 있습니다. 다른 분류를 고르려면 고른 것 하나를 먼저 빼 주세요." 고른 칩을 하나 빼면 안내가 사라지고 칩이 기본으로 돌아온다(시안 02).
- 탭을 바꿔도 다른 탭에 넣은 내용은 남는다. 제출할 때는 열려 있는 탭의 내용만 보낸다. 그래서 화면에서는 PDF와 글을 함께 보낼 수 없다.
- PDF를 고르자마자 화면이 형식과 크기를 검사한다. 어긋나면 파일을 받지 않고 상자의 테두리를 빨갛게 바꾸고 아래에 빨간 글을 보여 준다.
  - PDF가 아닐 때: "PDF 파일만 올릴 수 있습니다. 다른 형식이면 글 붙여넣기 탭에 글을 붙여넣어 주세요."
  - 5MB보다 클 때: "5MB보다 큰 파일은 올릴 수 없습니다. 파일을 줄이거나 글 붙여넣기 탭에 글을 붙여넣어 주세요."
- 글이 20,000자를 넘으면 칸의 테두리와 글자 수가 빨갛게 바뀌고 칸 아래 왼쪽에 "20,000자까지 넣을 수 있습니다. 글을 줄여 주세요."가 나온다. 이 상태로 제출하면 요청을 보내지 않는다.
- "추천 받기"를 누르면:
  1. 직무 분류도 없고 열린 탭도 비어 있으면 요청을 보내지 않고 버튼 위에 오류 안내 상자를 보여 준다: "직무 분류를 하나 이상 고르거나 이력서·자기소개서를 넣어 주세요."
  2. 직무 분류만 있으면(AI를 부르지 않는다) 버튼이 "추천 받는 중"(강조, 진행 중)으로 바뀌고, "지원자 프로필 만들기"와 "추천 만들기"를 차례로 요청한 뒤 추천 화면으로 넘어간다. 진행 중 표시 상자는 쓰지 않는다.
  3. 이력서·자기소개서가 있으면 두 카드가 흐려지고 버튼 자리에 진행 중 표시가 나온다(시안 04).
     - 첫 요청 동안: 제목 "이력서·자기소개서를 읽고 있습니다 (1/2)", 설명 "지원자 프로필을 만든 다음 추천을 만듭니다. 최대 1분쯤 걸릴 수 있습니다. 이 화면을 닫지 말고 기다려 주세요."
     - 둘째 요청 동안: 제목 "맞는 공고를 고르고 있습니다 (2/2)", 설명 "지원자 프로필은 만들었습니다. 최대 1분쯤 걸릴 수 있습니다. 이 화면을 닫지 말고 기다려 주세요."
- "지원자 프로필 만들기"가 AI 실패면 버튼 자리에 실패 안내가 나온다(시안 05). 제목 "이력서·자기소개서를 분석하지 못했습니다", 설명 "입력한 내용은 그대로 있습니다. 다시 시도하거나 내용을 고친 뒤 다시 시도해 주세요." 두 카드는 다시 고칠 수 있게 돌아오고, 입력한 내용은 모두 남아 있다. "다시 시도"는 지금 칸에 있는 내용으로 다시 제출한다.
- "지원자 프로필 만들기"가 입력을 거절하면 진행 중 표시를 거두고 서버의 메시지를 해당 자리에 빨간 글로 보여 준다. PDF에 관한 것(형식, 크기, 글 없는 PDF)은 PDF 상자 아래, 글 길이는 글 칸 아래, 나머지는 버튼 위다. 글이 없는 PDF의 권장 문구: "이 PDF에서 글을 읽을 수 없습니다. 스캔한 이미지로 보입니다. 글 붙여넣기 탭에 글을 붙여넣어 주세요."
- 지원자 프로필은 만들어졌는데 "추천 만들기"가 실패하면 그대로 추천 화면으로 넘어간다. 추천 화면이 실패 안내를 보여 준다(아래 "추천 실패").

## 화면 2: 추천

주소에 지원자 프로필 ID가 들어간다(예: `/profiles/12/recommendations`. 주소 모양은 구현 티켓에서 확정한다). 머리글의 단계는 2다. 시안: 추천 / 01~06.

화면을 열면 지원자 프로필 조회, 추천 조회, 로드맵 조회를 한다. 로드맵 조회는 "이미 로드맵이 있는가"를 알기 위한 것이며, 찾을 수 없음은 정상이다.

### 구성 (위에서 아래로)

1. **제목**: "추천 공고"(title). 아래에 "지원자 프로필에 맞는 공고입니다. 준비할 공고를 골라 로드맵을 만드세요."
2. **로드맵 있음 안내**(로드맵이 있을 때만): 옅은 남색 상자에 "이미 만든 로드맵이 있습니다. 로드맵에 넣은 공고는 아래에 체크해 두었습니다."와 오른쪽 "로드맵 보기"(글 버튼, 로드맵 화면으로 간다).
3. **지원자 프로필 카드**(읽기 전용)
   - 제목 "지원자 프로필"(h3), 아래에 "추천은 이 내용을 근거로 만들었습니다. 고칠 수 없으니, 틀린 곳이 있으면 입력부터 다시 해 주세요."(small). 오른쪽에 "입력부터 다시 하기"(글 버튼, 입력 화면으로 간다).
   - 선 아래에 라벨(너비 104, small-strong, `--text-muted`)과 값의 줄.
     - 관심 직무 분류: 남색 표시로 나열.
     - 전공: 글.
     - 기술: 회색 표시로 나열.
     - 경험: 한 줄에 하나씩, 앞에 가운뎃점.
   - 직무 분류만으로 만든 프로필(전공, 기술, 경험이 모두 비어 있음)은 관심 직무 분류 줄만 보여 주고 아래에 "이력서·자기소개서를 넣지 않아 전공, 기술, 경험은 비어 있습니다. 추천은 관심 직무 분류만으로 만들었습니다."(small, `--text-muted`)를 적는다. 이력서로 만들었는데 일부만 비어 있으면 그 줄을 빼고 보여 준다.
4. **진행 중 공고 구역**: 제목 "진행 중 공고"(h2)와 건수 "3건"(`--text-muted`), 아래에 "지금 지원할 수 있는 공고입니다. 순위가 높은 순입니다."(small). 그 아래 추천 카드를 순위 순으로.
5. **마감 공고 구역**: 제목 "마감 공고"와 건수, 아래에 "접수가 끝난 공고입니다. 다음 채용을 대비하는 참고용이며, 골라서 로드맵에 넣을 수 있습니다." 그 아래 추천 카드.
6. **아래 고정 줄**: 화면 아래에 붙어 있다(`position: sticky; bottom: 0`). 흰 바탕, 위 선 1px, 위아래 여백 16, 안쪽 너비 880. 왼쪽에 "고른 공고 2건"(body-strong)과 "진행 중 공고와 마감 공고를 함께 고를 수 있습니다."(small), 오른쪽에 "로드맵 만들기" 강조 버튼.

### 추천 카드

카드 하나가 추천 하나다. 안 여백 24, 카드 사이 14.

- 맨 왼쪽에 체크 칸.
- 첫 줄: 순위 "1위"(옅은 남색 알약, 구역 안의 순위), 기관 이름(small-strong, `--text-secondary`), 그 아래 공고 제목(h3).
- 공고 내용 세 줄. 라벨(small-strong, `--text-muted`, 너비 64)과 값.
  - 직무 분류: 회색 표시로 나열.
  - 접수 기간: "2026.11.16 (월) ~ 2026.12.11 (금)".
  - 전형 단계: 순서대로, 사이에 오른쪽 화살표. 단계 하나는 `--bg-subtle` 바탕의 작은 상자에 전형 종류(small-strong)와 날짜(small)다. 날짜가 없으면 전형 종류와 관계없이 "날짜 미정"(`--text-muted`)을 적는다. 마감 공고의 지난 날짜도 그대로 보여 준다.
- 추천 이유 상자(`--bg-subtle`, 모서리 8, 안 여백 14): 라벨 "추천 이유"(small-strong)와 이유(body). 직무 분류만으로 만든 추천은 "관심 직무 분류와 일치합니다."가 그대로 나온다.
- 체크한 카드는 테두리가 남색 2px로 바뀐다.
- 자격 조건 글은 보여 주지 않는다.

### 동작

- 카드를 누르거나 체크 칸을 누르면 고르거나 뺀다. 아래 고정 줄의 "고른 공고 N건"이 바로 바뀐다.
- 로드맵이 이미 있으면 로드맵에 넣은 공고를 미리 체크해 둔다. 아래 고정 줄의 버튼은 "로드맵 다시 만들기"로, 설명은 "다시 만들면 이전 로드맵과 직접 넣은 날짜가 지워집니다."(`--warning-default`)로 바뀐다(시안 02). 확인 창은 띄우지 않는다.
- 하나도 고르지 않고 버튼을 누르면 요청을 보내지 않고 설명을 "공고를 하나 이상 골라 주세요."(빨강)로 바꾼다. 버튼은 0건일 때도 누를 수 있게 둔다.
- 버튼을 누르면 "로드맵 만들기"를 요청한다. 기다리는 동안 추천 카드들이 흐려지고, 아래 고정 줄의 내용이 진행 중 표시로 바뀐다(시안 05). 제목 "로드맵을 만들고 있습니다", 설명 "고른 공고 2건에 맞춰 준비 단계와 할 일을 쓰고 있습니다. 최대 1분쯤 걸릴 수 있습니다. 이 화면을 닫지 말고 기다려 주세요." 끝나면 로드맵 화면으로 넘어간다.
- AI 실패면 아래 고정 줄의 내용이 실패 안내로 바뀐다. 제목 "로드맵을 만들지 못했습니다", 설명 "고른 공고는 그대로 있습니다. 다시 시도해 주세요. 이전에 만든 로드맵이 있었다면 그대로 남아 있습니다." 카드는 다시 고를 수 있게 돌아온다. 고른 공고를 바꾸면 실패 안내를 거두고 버튼으로 돌아간다.

### 상태

- **추천 실패**(시안 04): 지원자 프로필은 있는데 추천 조회가 찾을 수 없음일 때다. 입력 화면에서 추천 만들기가 실패해 넘어온 경우와 주소를 직접 연 경우가 같다. 지원자 프로필 카드 아래에 실패 안내만 보여 준다. 제목 "추천을 만들지 못했습니다", 설명 "지원자 프로필은 저장되어 있습니다. 다시 시도하면 추천만 새로 만듭니다." 구역과 아래 고정 줄은 없다. "다시 시도"를 누르면 "추천 만들기"를 요청하고, 그동안 같은 자리에 진행 중 표시(제목 "맞는 공고를 고르고 있습니다")를 보여 준다.
- **추천 0건**(시안 03): 두 구역이 모두 비었을 때다. 지원자 프로필 카드 아래에 빈 카드 하나를 보여 준다. 가운데 정렬로 동그라미 i 아이콘, "맞는 공고가 없습니다"(h3), "관심 직무 분류와 겹치는 공고가 지금은 없습니다. 오류가 아닙니다. 직무 분류를 바꿔 다시 해 보세요.", "입력부터 다시 하기"(보조 버튼). 아래 고정 줄은 없다. 빨간색을 쓰지 않는다.
- **한 구역만 0건**: 그 구역의 제목과 "0건"은 그대로 두고, 카드 자리에 점선 테두리 상자를 둔다. 진행 중 공고가 없으면 "맞는 진행 중 공고가 없습니다. 아래 마감 공고를 참고해 다음 채용을 대비해 보세요.", 마감 공고가 없으면 "맞는 마감 공고가 없습니다."
- **추천을 만든 뒤 접수가 끝난 공고**: 추천의 구역은 만든 시점의 것이므로 진행 중 공고 구역에 그대로 둔다. 조회 시점의 진행 중 여부가 "아님"이면 제목 줄 오른쪽에 회색 표시 "접수 마감됨"을 붙이고, 접수 기간 옆에 "추천을 만든 뒤 접수가 끝났습니다."(small, `--text-muted`)를 적는다. 고를 수는 있다.
- **지원자 프로필을 찾을 수 없음**: 화면 전체를 빈 카드 하나로 바꾼다. "지원자 프로필을 찾을 수 없습니다"(h3), "주소가 맞는지 확인해 주세요. 처음부터 다시 시작할 수 있습니다.", "처음부터 시작하기"(강조 버튼, 입력 화면으로 간다). 로드맵 화면도 같다.
- **불러오는 중**: 조회는 짧으므로 본문 자리에 "불러오는 중입니다."(body, `--text-muted`) 한 줄만 둔다. 시안은 없다.

## 화면 3: 로드맵

주소에 지원자 프로필 ID가 들어간다(예: `/profiles/12/roadmap`). 머리글의 단계는 3이다. 시안: 로드맵 / 01~05.

화면을 열면 로드맵 조회를 한다. 응답은 이미 일정 계산이 끝난 것이므로 화면은 계산하지 않고 받은 순서대로 보여 준다. 화면이 하는 계산은 둘뿐이다: 날짜 미정의 개수 세기, 할 일 기간의 날 수.

### 구성 (위에서 아래로)

1. **돌아가는 링크**: 왼쪽 화살표와 "추천으로 돌아가 공고 바꾸기"(글 버튼, 추천 화면으로 간다).
2. **제목**: "통합 로드맵"(title). 아래에 "2026.11.27 (금)에 만듦 · 고른 공고 4건 · 준비 단계 3개"(body, `--text-secondary`). 그 아래에 "준비 단계는 가장 이른 기한이 가까운 순서입니다. 기한을 누르면 날짜를 넣거나 고칠 수 있고, 넣으면 순서와 할 일 기간을 바로 다시 계산합니다."(small, `--text-muted`).
3. **반영 알림**(날짜를 넣거나 지운 직후에만): 옅은 청록 상자에 체크와 한 줄. 아래 "날짜 넣기" 참고.
4. **겹침 안내**(겹침이 있을 때만): 노랑 상자(모서리 12, 안 여백 20).
   - 세모 느낌표, "겹침 1건"(body-strong, `--warning-default`), "서로 다른 공고의 전형이 같은 날입니다. 둘 다 응시하기 어려울 수 있으니 기관 공지를 확인해 주세요."(small).
   - 겹친 날마다 흰 상자 하나: 왼쪽에 날짜(body-strong, 너비 130), 오른쪽에 겹친 것을 한 줄에 하나씩 "한국가상데이터공사 · 필기". 건수는 겹친 날의 수다.
5. **날짜 미정 안내**(날짜 미정이 하나라도 있을 때): 정보 안내 상자. "날짜 미정 5곳. 기관 공지에서 날짜를 확인하면 넣어 주세요. 날짜를 넣으면 그 준비 단계의 할 일 기간을 계산합니다." 개수는 모든 준비 단계의 공고별 기한 가운데 날짜 미정인 것의 수다.
6. **준비 단계 카드**: 응답의 순서대로 하나씩.

### 준비 단계 카드

- **제목 줄**: 남색 동그라미에 순서 숫자(1부터), 이름 "서류 준비"(h2. 전형 종류 뒤에 "준비"를 붙인다: 서류 준비, 필기 준비, 면접 준비, 기타 준비), "해당 공고 4건"(small, `--text-muted`). 오른쪽 끝에 표시 하나.
  - 다가오는 기한(오늘이거나 그 뒤인 기한)이 있으면: 남색 표시 "가장 이른 기한 12.04 (금)". 다가오는 기한 중 가장 이른 것을 적는다.
  - 기한이 모두 날짜 미정이면: 회색 표시 "기한 날짜 미정".
  - 날짜가 있는 기한이 모두 오늘보다 앞이면: 빨간 표시 "기한 지남".
- **공고별 기한**: 라벨 "공고별 기한"(small-strong, `--text-muted`) 아래에 해당 공고마다 한 줄. 줄 사이는 선 1px, 줄 안 위아래 여백 12.
  - 왼쪽: 기관 이름(body-strong), 그 아래 공고 제목(small, `--text-secondary`), 필요하면 그 아래 도움말 한 줄(small).
  - 오른쪽: 표시들, 그리고 날짜 버튼.
  - 줄의 순서: 응답의 순서 그대로다. 서버가 기한이 이른 순으로, 날짜 미정은 뒤에, 같으면 고른 순서로 준다. 화면은 다시 정렬하지 않는다.
  - "마감 공고"인지는 로드맵을 만든 날 기준이다(응답의 값). 만든 뒤에 접수가 끝난 공고는 마감 공고로 표시하지 않고 날짜도 그대로 보여 준다.
  - 줄의 경우:

    | 경우 | 표시 | 날짜 버튼 | 도움말 |
    |---|---|---|---|
    | 공고의 날짜 | 없음 | 공고의 날짜 | 없음 |
    | 사용자가 입력한 날짜 | "직접 입력" | 직접 입력 | 없음 |
    | 날짜 미정, 진행 중 공고 | 없음 | 날짜 미정 | 없음 |
    | 날짜 미정, 마감 공고 | "마감 공고" | 날짜 미정 | "마감 공고의 지난 날짜는 쓰지 않습니다. 다음 채용의 예상 날짜를 넣을 수 있습니다."(`--text-muted`) |
    | 마감 공고에 날짜를 넣음 | "마감 공고", "직접 입력" | 직접 입력 | 없음 |
    | 기한 지남(기한이 오늘보다 앞) | 위 표시에 더해 "기한 지남" | 그대로 | 없음 |
    | 겹침 | 위 표시에 더해 "겹침" | 그대로 | "가상국토정보원 필기와 같은 날입니다."(`--warning-default`). 상대가 여럿이면 쉼표로 잇는다 |

- **할 일**: 머리 줄에 "할 일", "기간"(너비 250), "비중"(너비 40, 오른쪽 정렬)을 small-strong `--text-muted`로 둔다. 아래에 할 일마다 한 줄(위 선 1px, 위아래 여백 10): 순서 숫자(`--text-muted`), 내용(body, 길면 줄바꿈), 기간(body-strong)과 날 수(small, `--text-muted`), 비중 "30%"(`--text-muted`).
  - 기간이 있는 준비 단계는 카드 맨 아래에 "기간은 로드맵을 만든 날(11.27)부터 가장 이른 기한 전날까지를 비중대로 나눈 것입니다." 여기서 가장 이른 기한은 로드맵을 만든 날보다 뒤인 기한 중 가장 이른 것이다. 날이 지나도 기간은 바뀌지 않는다.(small, `--text-muted`)를 적는다.
  - 기한이 모두 날짜 미정이면 기간 칸을 없애고 순서대로만 보여 준다. 카드 맨 아래에 정보 안내 상자: "기한이 모두 날짜 미정이라 할 일을 순서대로만 보여 줍니다. 위에서 날짜를 넣으면 기간을 계산합니다."(시안 04).
  - 남은 날 없음(날짜가 있는 기한이 모두 로드맵을 만든 날이거나 그 전)이면 기간 칸을 없애고, 카드 맨 아래에 오류 안내 상자: "기한이 모두 로드맵을 만든 날(2026.11.27)이거나 그 전이라 할 일에 기간을 붙이지 않았습니다. 날짜가 바뀌었다면 기한을 눌러 고쳐 주세요."(시안 05는 옛 문구다).
  - 남은 날 부족(기한까지 남은 날이 할 일 수보다 적음)이면 기간 칸을 없애고 할 일을 순서대로만 보여 준다. 카드 맨 아래에 정보 안내 상자: "기한까지 남은 날(2일)이 할 일(4개)보다 적어 할 일별로 나누지 않았습니다. 11.27 (금) ~ 11.28 (토) 안에 순서대로 진행해 주세요." 기간은 응답이 준 준비 단계 전체의 기간이다. 시안은 없다.
  - 한 준비 단계에 지난 기한과 남은 기한이 함께 있으면, 지난 기한의 줄에만 "기한 지남" 표시를 붙이고 할 일의 기간은 그대로 보여 준다. 시안은 없다.
  - 어느 경우인지는 응답의 "기간의 상태"(기간 있음, 날짜 미정, 남은 날 없음, 남은 날 부족)로 정한다. 화면이 날짜를 비교해 판단하지 않는다.

### 날짜 넣기

날짜 버튼을 누르면 그 줄이 `--bg-subtle` 바탕으로 바뀌고, 표시와 날짜 버튼 자리에 날짜를 넣는 칸이 나온다(시안 02, 05). 다른 화면으로 넘어가거나 창을 띄우지 않는다. 한 번에 한 줄만 열린다. 다른 줄의 날짜 버튼을 누르면 열려 있던 줄은 저장하지 않고 닫힌다.

- 칸의 구성(왼쪽부터): "넣은 날짜 지우기"(글 버튼, 사용자가 입력한 날짜가 있을 때만), 날짜 입력(`<input type="date">`, 너비 168, 높이 36, 남색 2px 테두리, 열리면 초점이 간다), "저장"(작게, 강조), "취소"(작게, 보조). 그 아래 오른쪽 정렬로 도움말 한 줄(small, `--text-muted`).
- 처음 값과 도움말:

  | 누른 것 | 처음 값 | 도움말 |
  |---|---|---|
  | 날짜 미정 | 비어 있음 | "기관 공지에서 확인한 날짜를 넣어 주세요." |
  | 공고의 날짜 | 그 날짜 | "저장하면 공고의 날짜 대신 이 날짜를 씁니다. 공고는 바뀌지 않습니다." |
  | 사용자가 입력한 날짜 | 그 날짜 | "지우면 공고의 날짜로 돌아갑니다. 공고에 날짜가 없으면 날짜 미정이 됩니다." |

- "저장"은 날짜가 비어 있거나 처음 값과 같으면 비활성이다. 날짜에 제한은 없다. 지난 날짜도 넣을 수 있고, 그러면 그 기한이 기한 지남으로 표시된다.
- Enter는 저장, Esc는 취소다.
- "저장"을 누르면 "날짜 넣기" 요청을 보내고, 버튼이 "저장 중"으로 바뀌며 칸 전체를 누를 수 없다. AI를 부르지 않으므로 진행 중 표시 상자는 쓰지 않는다.
- "넣은 날짜 지우기"를 누르면 날짜 없이 같은 요청을 보낸다.
- 응답(다시 계산된 로드맵)이 오면 화면 전체를 그 응답으로 다시 그린다. 준비 단계의 순서, 할 일의 기간, 겹침 안내, 날짜 미정 개수가 함께 바뀐다. 할 일의 내용과 비중은 그대로다.
- 다시 그린 뒤 제목 아래에 반영 알림을 보여 준다(`role="status"`). 다음에 날짜를 넣거나 화면을 떠날 때까지 남는다.
  - 넣었을 때: "한국가상데이터공사의 면접 날짜를 2027.01.13 (수)로 넣었습니다. 순서, 할 일 기간, 겹침을 다시 계산했습니다."
  - 지웠을 때: "한국가상데이터공사의 면접에 넣은 날짜를 지웠습니다. 순서, 할 일 기간, 겹침을 다시 계산했습니다."
- 요청이 실패하면 칸을 연 채로 두고 도움말 자리에 "날짜를 저장하지 못했습니다. 다시 시도해 주세요."(빨강)를 보여 준다. 서버가 메시지를 주었으면 그것을 쓴다.

### 상태

- **로드맵이 아직 없음**: 로드맵 조회가 찾을 수 없음이고 지원자 프로필은 있을 때다. 빈 카드 하나: 동그라미 i 아이콘, "아직 만든 로드맵이 없습니다"(h3), "추천 공고에서 준비할 공고를 골라 로드맵을 만들어 주세요.", "추천 공고로 가기"(강조 버튼).
- **지원자 프로필을 찾을 수 없음**: 추천 화면과 같다.
- **AI를 기다리는 중, AI 실패**: 로드맵 화면에는 없다. 로드맵은 추천 화면에서 만들고, 날짜 넣기는 AI를 부르지 않는다.

## 명세에 반영한 것

디자인하면서 명세(#1)와 어긋난 곳을 2026-11-28에 명세와 티켓(#5~#13)에 반영했다. 경위는 `docs/02-design-decisions.md`의 "화면 디자인 반영"에 있다.

### API 응답에 더한 값

- 로드맵 응답: 로드맵을 만든 날, 고른 공고마다 공고 ID와 로드맵을 만든 날 기준의 진행 중 여부, 기한마다 기한 지남 여부, 준비 단계마다 기간의 상태, 겹침 목록의 모양(겹친 날마다 날짜와, 겹친 것마다 공고 ID, 기관 이름, 전형 종류).
- 추천 응답: 공고 ID.
- 오류 응답: 종류를 가르는 코드(AI 실패, 찾을 수 없음, 입력 없음, 직무 분류 규칙 위반, PDF 형식·크기, 글이 없는 PDF, 글 길이 초과, PDF와 글을 함께 보냄).

### 명세가 받아들인 화면의 동작

- PDF와 글을 탭으로 나눠 열린 탭의 내용만 보낸다. API에 둘을 함께 보내면 거절하는 것은 그대로다.
- PDF의 형식과 크기, 글의 길이를 화면이 먼저 검사한다. 서버도 검사한다.
- 로드맵이 있으면 추천 화면에서 로드맵에 넣은 공고를 미리 체크해 둔다.
- 찾을 수 없음 화면 둘, 날짜 미정 개수 안내, 날짜 반영 알림, 글자 수 표시, "접수 마감됨" 표시.

### 디자인과 다르게 정한 것

- 준비 단계 안의 공고 줄은 화면이 정렬하지 않는다. 서버가 순서대로 준다.
- 로드맵의 "마감 공고" 표시는 조회 시점이 아니라 로드맵을 만든 날 기준이다.

### 일정 규칙을 고친 것

화면의 상태를 그리다가 찾은 규칙의 빈틈 다섯 개를 고쳤다. 이 문서의 "화면 3: 로드맵"은 고친 규칙에 맞춰 다시 적었다.

1. 공고의 날짜를 쓰는지는 로드맵을 만든 날 기준으로 한 번 정한다. 접수 마감일이 지나도 필기·면접 날짜가 사라지지 않는다.
2. "기한 지남"과 "할 일에 기간이 없음"을 나눴다. 기간이 없는 이유는 날짜 미정, 남은 날 없음, 남은 날 부족 셋이다.
3. "기한 지남"은 오늘 기준으로, 공고별 기한마다 판단한다. 할 일의 기간은 로드맵을 만든 날 기준으로 고정한다.
4. 남은 날이 할 일 수보다 적으면 할 일별로 나누지 않고 준비 단계 전체의 기간만 보여 준다.
5. 할 일의 기간은 로드맵을 만든 날보다 뒤인 기한 중 가장 이른 것으로 계산한다. 지난 기한 하나가 준비 단계 전체의 기간을 없애지 않는다.

### 시안에 없는 모습

규칙을 고치면서 생긴 모습이다. Figma 시안과 `docs/design/`의 그림에는 없고 이 문서의 글로만 정해져 있다. #9에서 기존 안내 상자와 표시를 써서 만든다. 시안을 다시 그리면 이 목록을 지운다.

- 남은 날 없음의 안내 상자. 시안 `roadmap-05-states.png`의 "기한 지남" 안내 문구는 옛 규칙의 것이다.
- 남은 날 부족의 안내 상자.
- 공고별 기한 줄에 붙는 "기한 지남" 표시.
- 한 준비 단계에 지난 기한의 줄과 기간이 있는 할 일이 함께 있는 모습.
- 좁은 화면. 규칙만 "화면 틀"에 적었다.
